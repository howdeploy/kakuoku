# Запуск веб-версии на Windows, Linux и macOS

Backend, SQLite и обработчики медиа работают в Linux-контейнере.
Интерфейс открывается в браузере. Node.js, Python, FFmpeg и компилятор на
компьютере пользователя для обычного запуска не требуются: они входят в образ.
GUI для работы с подключённым каталогом будет отдельным этапом.

## Подготовка

| ОС компьютера | Среда запуска |
|---|---|
| Windows | [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/) с WSL 2 и Linux-контейнерами |
| macOS, Intel или Apple silicon | [Docker Desktop](https://docs.docker.com/desktop/setup/install/mac-install/) |
| Linux | [Docker Engine](https://docs.docker.com/engine/install/) и [Compose v2](https://docs.docker.com/compose/install/linux/) |

Docker должен быть запущен до старта приложения. Образ собирается для
архитектуры Docker-хоста; код обработчика медиа предусматривает amd64 и arm64.
Для медиа, vision и локальных субтитров нужны Landlock/seccomp в ядре среды
Docker. При их недоступности обработчик сообщает ошибку; запуск без защиты
не используется. Полная работа этих функций на Windows/macOS пока не проверена.

## Первая установка

Откройте терминал в папке исходников, содержащей `compose.yaml`.
Команды одинаковы в PowerShell и терминале Linux/macOS:

```sh
docker volume create kakuoku-production-data
docker compose build --pull
docker compose up -d
```

Откройте **http://localhost:3101**. Ключ AI вводится в настройках приложения.
Остановка — `docker compose stop`, повторный запуск — `docker compose start`.
Для существующей установки сохраняйте выбранный volume и сначала прочитайте
[совместимость данных](rename-migration.md). Не создавайте замену хранилищу,
которое уже содержит заметки.

По умолчанию постоянные данные находятся в отдельном Docker volume
`kakuoku-production-data`. Его расположением на компьютере управляет Docker;
личная точка монтирования не записана в коде. В контейнере каталог всегда
называется `/app/data`: это внутренний путь, одинаковый на всех трёх ОС.

## Своя папка данных

Для новой установки можно подключить существующий каталог вместо volume:

1. Создайте отдельную папку данных. Она должна разрешать запись контейнерному
   пользователю UID/GID `1000:1000`; в Docker Desktop предоставьте Docker доступ
   к этому каталогу, если он требуется настройками общего доступа.
2. Создайте локальный `.env` рядом с `compose.yaml`, ориентируясь на
   `.env.example`. Существующий `.env` не перезаписывайте.
3. Задайте `KAKUOKU_DATA_DIR` равным своему абсолютному пути. На Windows
   используйте прямые слеши, например `C:/KakuokuData`; на остальных ОС —
   абсолютный путь к выбранному каталогу. Для пробелов или символа `$` заключите
   значение в одинарные кавычки в `.env`.
4. Скопируйте `compose.override.example.yaml` в `compose.override.yaml`.
   Существующий override, в том числе созданный помощником переноса, сохраняйте:
   этот шаблон не предназначен для его перезаписи.
5. Выполните команды первой установки. Compose подхватит локальный override
   и подключит папку в `/app/data`. При пустой переменной или отсутствующей
   папке запуск остановится с ошибкой; каталог по ошибочному пути не создаётся.

Эта настройка выбирает хранилище, а не переносит его. Если заметки уже есть,
не подключайте вместо них пустую папку: сначала остановите приложение,
сохраните и перенесите весь каталог данных по [инструкции резервного копирования](backend.md).
На Linux доступен существующий [помощник переноса](../README.ru.md#настройки).
Он не поддерживает Windows/macOS и не перезаписывает вручную созданный override.

В папке находятся SQLite с WAL/SHM и каталог `media`; копируйте их вместе.
Для первой установки проще использовать Docker volume: подключение папки
зависит от прав и файловой системы конкретного компьютера.

## Локальные настройки и изоляция

`.env`, локальные Compose overrides, `.data`, базы, ключи и логи исключены
из Git. Build context задан разрешающим списком: рабочие заметки, локальные
пути и настройки не включаются в образ. При ручном архивировании исходников
также исключайте эти файлы: архиватор не применяет `.gitignore` автоматически.

Шаблон папки меняет только источник `/app/data`. Backend сохраняет non-root,
read-only корень, сброшенные capabilities, `no-new-privileges`, лимиты ресурсов
и публикацию порта только на `127.0.0.1`. Домашняя папка целиком и Docker socket
в контейнер не передаются. Ограничения — в [контракте backend](backend.md).

Настройка опирается на официальные правила [bind mounts](https://docs.docker.com/engine/storage/bind-mounts/),
[переменных Compose](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/)
и [объединения mounts по target](https://docs.docker.com/reference/compose-file/merge/#unique-resources).
Фактический запуск на Windows/macOS ещё требует проверки на этих ОС.
