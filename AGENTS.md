# Kakuoku

Рабочее имя проекта. Пользовательский чат — на русском; GitHub — на английском.

- Сначала согласовываем дизайн через работающую веб-демку с Agentation.
  Комментарии читаются из `GET /api/feedback` на локальном demo-сервере.
- Визуальная основа: крупная асимметричная лента Google Keep и аватарки
  пользователя. Решения и SL source receipts — в `docs/design.md`.
- Refero — методология дизайна; SL UI — реальные исходники выбранных
  компонентов. Не заменять подключённый controller похожей перерисовкой.
- Не запускать тесты, build, lint, typecheck, браузер, Electron, визуальную
  проверку и субагентов без прямой просьбы пользователя. Прочитать изменения
  перед handoff, честно назвать непроверенное. Не объявлять runtime audit пройденным.
- Сохранять разделение: web UI → HTTP API → store / agent. Electron — оболочка.
  Будущие Android и canvastty используют этот API; не добавлять их заранее.
- По умолчанию GhostMetal API: `https://api.ghostmetal.io/v1`, `glm-5.3-long`.
  По прямому запросу пользователя настройки позволяют менять публичный HTTPS
  эндпоинт OpenAI-совместимого API, ключ, три промпта и режим агента.
  Ключ сохраняется только в серверной SQLite; env — fallback до явной замены
  или удаления ключа в настройках. GET возвращает только hasApiKey.
  Не сохранять ключ в `VITE_`, localStorage, логах или клиентской базе.
  Платные запросы не выполнять без решения пользователя о подключении.
- Production — Docker Compose, loopback `127.0.0.1:3101`, по умолчанию отдельный постоянный
  external volume `kakuoku-production-data` (или существующий, явно выбранный
  через `KAKUOKU_DATA_VOLUME`) только в `/app/data`. Удаление контейнера
  сохраняет данные; удаление volume — отдельное явное действие пользователя.
  Без домашних папок, host network, socket, privileged и устройств; non-root,
  read-only корень, cap_drop ALL, no-new-privileges и лимиты ресурсов.
  Демобаза `.data/demo` остаётся отдельно. Runtime-маркеры контейнера и наличие
  Compose не доказывают фактическую изоляцию. Запуск описан в `docs/backend.md`.
- Веб-версия на Windows, Linux и macOS использует тот же Linux-контейнер;
  Docker остаётся слоем изоляции. Инструкция — `docs/deployment.md`.
  Личные пути допустимы только в локальном `.env` / игнорируемом Compose override,
  не в коде и не в публикуемых примерах. `compose.override.example.yaml` — шаблон
  выбора своей папки, без автоматического переноса данных. Полноценный GUI отложен.
- Агент получает текущую переписку и материалы только этой заметки.
  Веб-права — только `read_url` / `search_web` и `youtube_transcript` для
  ссылок пользователя в текущей заметке; `finish_research` задаёт
  формат окончательного ответа и не предоставляет доступа к данным.
  Материалы подаются в контекст в течение 30 минут после последнего сообщения
  или действия обработки; истечение окна не удаляет архив из SQLite.
  Исключение по прямому запросу пользователя: явная «Сортировка» передаёт
  отдельному вызову модели все сохранённые заметки для создания общих сводок,
  без инструментов; исходные чаты не удаляются. Обычный чат по-прежнему получает
  только свою переписку.
  Не добавлять shell, filesystem, SQL, произвольные MCP, доступ к другим
  заметкам или пользовательским каталогам. Нельзя снимать SSRF/DNS/redirect checks.
- Деморежим не вызывает LLM. Примеры помечены. По запросу пользователя
  доступны model и visionModel (same/off или выбранная модель).
  До 4 последних PNG/JPEG/WebP/GIF текущей заметки передаются в image_url
  как JPEG-копии до 1600px и 1 МиБ; GIF — только первый кадр. Оригиналы
  не изменять. Подготовка в C sandbox получает только read-only fd одного
  файла, без ключей/базы/сети. Видео и звук моделью не распознаются.
  Превью/сортировка получают только текст и метаданные, не пиксели.
  Не путать vision с images/generations; генератор не является моделью анализа.
- Режимы: chat — без web tools; research — с разрешёнными web tools;
  notes — без любых вызовов модели, включая превью и сортировку.
  Настройки применяются к новым операциям; выполняющаяся использует свой snapshot.
- Инструменты настраиваются отдельно: поиск builtin/Tavily/Brave/off,
  субтитры YouTube local/Supadata/off. Ключи только в SQLite, GET возвращает
  hasKeys; сохранение без сетевой проверки. Платного fallback нет.
  Локальный Python worker запускается фиксированной командой через
  Landlock/seccomp без сети, ключей и доступа к data; HTTP выполняет сервер
  только к разрешённым путям YouTube с DNS/IP-проверками, без redirects.
  Субтитры — речь, не распознавание кадров или аудио; отсутствие не имитировать.
- Лимит исследования researchMaxCalls настраивается от 4 до 12, по умолчанию 12.
  Последнее обращение только для итога; deadline 660 секунд и контекст 350k
  сохранены. Готовый итог может завершить запрос до исчерпания лимита.
- Внешние базы знаний не обновлять без отдельного запроса.
- Перенос данных выполняет только `host/` на Linux, вне app-контейнера:
  `npm run host`, loopback 3102, строгие Origin/Host и токен действий.
  Выбранная папка подключается как единственный `/app/data` через локальный
  игнорируемый `compose.override.yaml`. Не копировать реальные пути в код.
  Перед переносом — блокировка API, остановка, полная копия и сверка файлов;
  источник и резервная копия сохраняются. До committed допускается возврат
  подключения; после допуска записей нельзя автоматически вернуться к старой
  базе. Docker socket и каталоги хоста в app не подключать.
- Галерея использует GET /api/media с курсором; старые BLOB-фото не переносить.
  Видеопостеры — фиксированный FFmpeg в существующем C sandbox, только
  read-only fd одного файла, без сети/ключей/базы; ошибки не удаляют оригинал.
  Фоновые ответы принадлежат App, не Chat. Закрытие во время ответа ставит
  обновление превью после lock, не отменяет запрос и не запускает новый ответ.
  Карточки восстанавливают agentWorking/previewPending через /api/activity.
